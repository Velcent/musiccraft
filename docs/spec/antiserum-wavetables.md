# Antiserum: wavetable sources and editor

Roadmap Phase 3. Where Antiserum's wavetables come from (factory tables,
imported audio) and how they are edited. The synth core (`docs/spec/antiserum.md`)
plays a `Wavetable` built from frames; this spec covers the frames themselves.

## Crate

`musiccraft-wavetables` holds the editable table and every operation on it.
It runs on the main thread only (it allocates freely) and knows nothing of the
synth, the app or plugin formats. Its output, `Table::samples()`, is what
`musiccraft_antiserum::Wavetable::new` takes.

- `Table`: 1 to 256 frames of 2048 samples (`FRAME_LEN`, `MAX_FRAMES`, the
  same limits as the synth). Samples are finite; anything else becomes 0 on
  the way in. A table never has zero frames.
- `Table::frame(i)` and `Table::frames()` read it; changes go through `Op`s.

## Factory tables

Generated by code, so no file is copied or shipped. `factory::names()` lists
them in this order and `factory::table(name)` builds one. Each is 64 frames
unless noted, and every frame is normalized to a peak of 1 (silent frames
stay silent).

| Name | Frames morph from … to … |
| --- | --- |
| `basic` | sine → triangle → saw → square (the synth's default) |
| `analog` | saw → square → triangle with a soft, rounded edge (one-pole smoothed) |
| `pwm` | square at 50 % pulse width → 2 % |
| `additive` | 1 harmonic → 64 harmonics of a saw series, one more per frame |
| `odd_even` | odd harmonics only (square-like) → even harmonics only |
| `formant` | the vowels a → e → i → o → u, as a 110 Hz-like saw shaped by two formants |
| `fm` | a sine modulated by a sine at ratio 1, index 0 → 8 |
| `fm_ratio` | index 2, modulator ratio 1 → 8 |
| `sync` | a hard-synced saw, slave/master ratio 1 → 8 |
| `noise` | 16 frames of random spectra with smooth 1/f slopes (fixed seed), crossfaded |
| `harmonic_morph` | random harmonic weights (fixed seed) blending from bright to dark |

Generators are deterministic: the same name always builds the same table
(random tables use a fixed seed). Tests check each table's spectrum (for
example, `additive` frame 10 has exactly 10 harmonics) rather than checksums,
which would differ by platform maths libraries.

## Import

`import::from_wav(bytes, Slicing)` reads a WAV file (any of the PCM or float
formats `hound` decodes). Channels are averaged to mono. The sample rate is
ignored: a wavetable is a list of cycles, not a recording at a pitch.

`Slicing`:

- `Auto` (the default):
  - If the file has a `clm ` chunk whose text starts with `<!>` followed by a
    frame length (decimal digits), the file is a wavetable with frames of that
    length (D4: an open convention used by many wavetable synths).
  - Otherwise, if the length is a whole number (1–256) of 2048-sample frames,
    it is a wavetable of 2048-sample frames.
  - Otherwise, a file of at most 4096 samples is one single cycle.
  - Otherwise, it is sliced by pitch.
- `Wavetable(len)`: consecutive frames of `len` samples (a partial last
  frame is dropped).
- `Fixed(len)`: like `Wavetable(len)` but meant for arbitrary audio; when it
  would give more than 256 frames, 256 frames are taken evenly spaced
  across the file.
- `Pitch`: the fundamental is detected (`musiccraft_dsp::pitch`, the median
  of its estimates). Each frame is one period, read at evenly spaced
  positions across the file: one frame per period up to 256 frames. A file
  with no detectable pitch is an error.
- `SingleCycle`: the whole file is one frame.

Every slice is resampled to 2048 samples (cubic Hermite interpolation,
wrapping around the cycle). Frames past 256 are dropped. A file with no whole
frame is an error.

`import::from_wav_file(path, Slicing)` reads the file and calls the above.

## Export

`export::to_wav(&Table)` writes a mono 32-bit float WAV (48 kHz, an arbitrary
rate) with every frame end to end and a `clm ` chunk `<!>2048 MusicCraft`, so
our own import (and other synths that read the convention) reads it back with
the right frame size. Import after export gives back the same table.

## Editing

An `Op` is a plain description of one change, applied with `Op::apply(&mut
Table) -> Result<(), String>`. Errors (an out-of-range frame, a bad formula)
leave the table untouched. Frame numbers are 0-based; ranges are inclusive.

| Op | Effect |
| --- | --- |
| `Replace(Table)` | The whole table (a factory table, an import). |
| `Draw { frame, start, values }` | Writes `values` (clamped to ±1) into the frame from sample `start`, wrapping. |
| `SetPartial { frame, harmonic, magnitude, phase }` | Rebuilds the frame with one partial (1–1023) changed. Magnitude is relative to a full-scale sine (1 = peak 1); phase is in turns (0–1). |
| `Formula { text, first, last }` | Fills frames `first..=last` from a formula of `x` (phase 0–1 within the frame) and `y` (0–1 across the range; 0 if it is one frame). |
| `Morph { first, last, mode }` | Rewrites the frames strictly between `first` and `last` as a morph between those two. `Crossfade` blends samples; `Spectral` blends each partial's magnitude linearly and its phase along the shorter way round. |
| `Normalize { first, last }` | Scales each frame to a peak of 1. |
| `RemoveDc { first, last }` | Subtracts each frame's mean. |
| `ReverseSamples { first, last }` | Plays each frame backwards. |
| `ReverseFrames` | Reverses the order of the frames. |
| `InsertFrame { at }` | Inserts a copy of frame `at` after it (up to 256). |
| `DeleteFrame { at }` | Removes a frame (never the last one left). |

Partials: `spectrum::partials(frame)` gives (magnitude, phase) for harmonics
1–1023 in the units above (the Nyquist bin has no phase and is left out);
`SetPartial` keeps all the others, and DC.

Formulas use `musiccraft-formula`'s table mode, `Formula::parse_table`: the
same operators and functions as controller formulas, with the variables `x`,
`y` and `pi` (and not `t` or `bar`). Example: `sin(x*pi*2) * (1-y)`.
`Formula::parse` (controllers) keeps refusing `x` and `y`.

Undo: a gesture (a drag, a click, a button) reports `Begin` once and then its
ops. A caller snapshots the table at `Begin`; Phase 6 turns this into
commands on Antiserum channels.

## Editor (`musiccraft-editors::wavetable`)

An egui editor for one table. Like the effect editor it never changes the
table itself: it reports `WavetableEdit`s (`Begin`, `Op(Op)`, `Factory(name)`)
and the caller applies them. Its own view state (selected frame, tab,
formula text, morph mode) is a `WavetableEditor` the caller keeps.

- **Toolbar:** a factory table menu, frame count, the selected frame
  (`3 / 64`), and buttons for normalize, remove DC, reverse samples, reverse
  frames, insert frame and delete frame (on the selected frame, or on all
  frames with *All* ticked), and morph (from frame 0 to the last, with a
  crossfade/spectral switch).
- **3D frame stack:** every frame (at most 64 drawn, evenly spaced) as a line
  drawn in perspective, back to front, the back ones fainter. The selected
  frame is highlighted. Clicking a frame's line selects it; scrolling over the
  stack moves the selection.
- **Tabs** for the selected frame:
  - *Draw:* the frame as a waveform; dragging draws through the samples the
    pointer passes over (one `Begin`, then a `Draw` per frame of the drag,
    with the samples in between interpolated so no gap is left).
  - *Harmonics:* bars for partials 1–64, magnitude on top (drag a bar up or
    down) and phase below (drag); each change is a `SetPartial`.
  - *Formula:* a text field and *Apply* to the selected frame or all frames;
    a parse error shows under the field and nothing is reported.

Without a renderer the editor runs headlessly, which the tests use.
An example, `cargo run -p musiccraft-editors --example wavetable`, opens it on
the factory tables in a window. The app and plugins show it from Phase 6.

## CLI

`musiccraft-cli wavetable …` exercises all of the above without a UI:

- `wavetable list`: the factory tables and their frame counts.
- `wavetable export <name> <out.wav>`: writes a factory table.
- `wavetable import <in.wav> <out.wav> [auto|single|pitch|fixed:<len>|frames:<len>]`:
  imports and writes the result, printing the frame count.
- `wavetable formula <expr> <frames> <out.wav>`: a table from a formula.

## Sources

- Own design. Factory tables are generated from textbook waveforms and
  synthesis methods (additive series, FM after Chowning, hard sync, formant
  filtering with textbook vowel formants); no wavetable file is copied.
- The `clm ` chunk convention (frame length after `<!>`): read and written for
  interoperability under owner decision D4. Nothing else from any other
  product's file formats is used.
- RIFF/WAVE: the public format description.
- Cubic Hermite (Catmull-Rom) interpolation and FFT-based harmonic editing:
  standard DSP literature.
